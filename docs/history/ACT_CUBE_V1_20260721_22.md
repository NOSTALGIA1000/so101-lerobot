## V1 真机结果（定性记录）

| 测试情况 | 历史观察 | 可支持的结论 |
| --- | --- | --- |
| 初期推理 | 有下探和夹爪动作，但未接近/夹住 CUBE | 不能把有轨迹当成识别并抓取成功 |
| 调整相机映射后 | 用户反馈“表现不错，碰到 CUBE” | 视角对应是优先检查项；不能证明唯一原因 |
| 限幅 0.5 | 动作保守，较多 clamped warning | 限幅会改变实际执行轨迹 |
| 限幅 1.0，短轮次 | 更能靠近或触碰 CUBE | 当时适合作为后续短测起点，非通用安全保证 |
| 限幅 1.0，20 秒 | 曾出现总线读位置无回包 | 应停测并检查通信、供电、线材；不能断言具体损坏 |

历史错误：`Failed to sync read 'Present_Position' on ids=[1,2,3,4,5,6]`、`[TxRxResult] There is no status packet!`。随后只读检查曾恢复，记录不足以证明是模型、WSL 或某个舵机单独导致。

目标是 10 次中至少 7 次夹住并离桌稳定保持 3 秒；本对话没有完整逐次评测表，未达到可报告的 70% 验收证据。不能填造成功次数、控制频率或验证损失排名。

## 主要教训

1. 先确认实际图像内容和输入键，再分析抓取偏差；相机能打开、图像非黑，不等于视角正确。
2. 验证损失、训练步数、触碰方块均不能替代完整抓取成功率。
3. 改动相机、标定、限幅、任务或后处理时留版本记录，否则模型对比不公平。
4. 旧教程的 `control_robot.py` / `python -m lerobot.record --policy.path` 与本机版本不通用。本历史环境用 `lerobot-record` 采集、`lerobot-rollout` 推理。
5. 真机测试结束需停止目标 rollout、相机桥接及相关后台任务，保存结果，确认机械臂安全落位并断舵机电源。不要泛化成结束电脑上所有进程。
